프로젝트 시나리오 — 경기 분석 데이터 인수 검사

1. 상황

경기 분석 서비스를 준비하는 팀이 여러 시즌의 수집 데이터를 하나의 CSV 묶음으로 인수했습니다. 출전자 프로필, 랩 타이밍, 피트 이벤트, 타이어 구간, 기상 관측, 경기 메타데이터가 서로 다른 수집·병합 경로를 거쳐 저장되어 있습니다.

각 파일은 열리고 기본 형식도 유지되어 있지만, 일부 분석 결과 사이에 설명되지 않는 불일치가 보고되었습니다. 단순한 파일 파손보다는 수집·보정·병합 과정의 부분적인 데이터 품질 문제가 의심되는 상황입니다.

2. 팀의 역할

이번 팀 프로젝트에서 출제팀은 인수 데이터와 명세서를 제공하고, 상대팀은 데이터 품질 검토를 맡습니다. 양 팀에 서로 다른 두 버전의 문제를 배포하는 구조가 아니라, 이 배포본 한 세트를 상대팀이 검토하는 구조입니다.

상대팀은 각 파일을 독립적으로 살펴보는 데서 그치지 않고, 필요한 범위에서 데이터 사이의 관계와 기록의 맥락을 확인하여 문제를 설명합니다. 모든 특이값이 이번 프로젝트에서 주입한 오류인 것은 아닙니다.

3. 검토 목표와 산출물

증거가 있는 오류를 식별하고, 변경이 필요한 대상과 그대로 보존해야 할 대상을 구분합니다. 원래 값을 충분히 뒷받침할 수 있을 때만 복구안을 제시합니다. 누락이나 모호한 변경처럼 값이 유일하게 결정되지 않는 경우에는 확인된 사실과 추정을 분리합니다.

결과 문서에는 대상 파일과 식별 키, 관찰한 현상, 판단에 사용한 근거, 제안한 조치, 남아 있는 불확실성을 남깁니다. 구체적인 풀이 순서·탐지 코드·정답 위치는 이 시나리오에서 제공하지 않습니다.

4. 보존 원칙

배포받은 CSV는 별도로 보관하고 작업 사본에서 검토합니다. 원본에 이미 있었을 수 있는 결측, 긴 기록, 시즌별 표기 차이 등을 추측만으로 일괄 정규화하지 않습니다. 분석 결과는 문제의 존재를 주장하는 근거와 복구값을 주장하는 근거를 구분하여 설명합니다.

사용자 제공 CSV 및 오염 룰북을 기준으로 작성한 프로젝트 자료입니다.
