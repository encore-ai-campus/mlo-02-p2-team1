정제 전후 모두 WARN인 7개 항목은 아래 표와 같이 원천 특성으로 남는 항목입니다.

## 3. 실행 방법

pandas:

```powershell
python -m pipeline.validate_cleaned               # 기본: data/03_cleaned + data/01_raw/f1_extra_data(없으면 zip)
```

결과는 `data/04_reports/validation/`에 생성됩니다: `validation_report.md`(GitHub에서 보는 요약)·`validation_report.html`(첫 표가 행 수 대사), `row_reconciliation.csv`, `validation_result.csv`, `validation_samples.csv`, `null_profile.csv`, `validation_before_after.csv`(정제 전후 비교). ERROR 위반이 있으면 종료 코드 1을 반환합니다. 정제 전 비교를 건너뛰려면 `--no-baseline`을 붙입니다.

MySQL: 저장소 루트에서 `sql/01` → `02` → `03` → `04` → `05` 순서로 실행합니다. MySQL 8.4에서는 `03_validate_cleaned.mysql84.sql`을 사용합니다. `02b_reload_repair_detail.sql`(수정 이력 repair_detail 재적재)은 02 수정 전 방식으로 적재한 DB를 보정할 때만 씁니다. 자세한 절차는 [web/README.md](../web/README.md)에 있습니다.
