# 데이터 검증

[README.md](../README.md)의 「데이터 검증」 상세입니다. 정제 결과(6종)와 추가 데이터(5종)를 함께 검사합니다. 검사 정의는 [validation_checks.csv](../data/02_reference/standard_dictionary/validation_checks.csv)(VC01~VC71)이고 pandas와 SQL이 같은 ID·규칙을 씁니다.

## 1. 검사 항목

| 분류 | 검사 | 예 |
|---|---|---|
| 결측 | VC01~VC04 | 식별키 공백, 컬럼별 결측 프로파일, 결측을 0으로 채운 값 |
| 중복 | VC10~VC13 | 자연키 중복, 완전 중복 행, 같은 경기 순위 중복, 한 세션 내 이름 중복 |
| 참조 | VC20~VC27 | 세션·드라이버 참조, meeting_key 일치, 예선 그리드↔Race 매핑 |
| 범위·형식 | VC30~VC34 | 숫자·일시 변환, 허용 범위, 허용 코드, 완주 상태 동시 True |
| 정합성 | VC40~VC45 | 팀당 드라이버 수, 섹터 합계, 피트 시간 컬럼, 스틴트 중첩 |
| 포인트 | VC50~VC53 | 기본 포인트 재계산, 드라이버 합 = 팀 합, 경기당 101점 |
| 대사 | VC60~VC62 | 원본 행 = 정제 후 행, 격리 행, 복구 기록 없는 값 변경 |
| JOIN 행 증폭 | VC70~VC71 | 드라이버 JOIN 후 행 증가, 랩↔스틴트 범위 중복 매칭 |

## 3. 실행 방법

pandas:

```powershell
python -m pipeline.validate_cleaned               # 기본: data/03_cleaned + data/01_raw/f1_extra_data(없으면 zip)
```

결과는 `data/04_reports/validation/`에 생성됩니다: `validation_report.md`(GitHub에서 보는 요약)·`validation_report.html`(첫 표가 행 수 대사), `row_reconciliation.csv`, `validation_result.csv`, `validation_samples.csv`, `null_profile.csv`. ERROR 위반이 있으면 종료 코드 1을 반환합니다.

MySQL: 저장소 루트에서 `sql/01` → `02` → `03` → `04` → `05` 순서로 실행합니다. MySQL 8.4에서는 `03_validate_cleaned.mysql84.sql`을 사용합니다. `02b_reload_repair_detail.sql`(수정 이력 repair_detail 재적재)은 02 수정 전 방식으로 적재한 DB를 보정할 때만 씁니다. 자세한 절차는 [web/README.md](../web/README.md)에 있습니다.
